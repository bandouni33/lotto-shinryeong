# 로또신령 — 생성형 AI 활용 저작물 명세 준비자료

이 문서는 "로또신령" 앱(번개조합·안티/액땜조합·자동구매·통계센터·타로점)의 실제 소스코드와
콘텐츠 데이터를 직접 확인해 정리한 근거자료입니다. 저작권 등록 신청서의 정확한 항목 구성은
별도로 진행 중인 상담(다른 대화창)에 맞춰주시고, 이 문서는 "③ 인간의 창작적 표현" 등에 채워
넣을 구체적 근거·사실관계를 제공하는 용도입니다. 제가 직접 관찰하지 못한 "왜 이렇게
설계했는가"에 대한 주관적 동기 서술은 [사용자 보완 필요]로 표시해뒀으니, 실제 기획 의도를
아는 그대로 채워 넣으시면 됩니다.

## 2. 번개조합

### 2.1 기능 설명
사용자가 삭제수(빼고 싶은 번호) / 고정수(반드시 포함할 번호, 최대 5개) / 행운수(가족 생일
기반 개인화 번호)를 선택하면, 나머지 자리를 채워 6자리 로또 조합을 여러 게임 생성한다.

### 2.2 인간의 창작적 설계 — 핵심 알고리즘 구조
번호 하나를 뽑는 방식이 여러 층으로 설계되어 있고, 각 층의 판단 기준이 전부 명시적 지시로
결정됨:

1. **번호별 가중치 추첨**: 완전 균등 무작위 대신, 1회부터 최신 회차까지 실제 당첨번호 출현
   횟수를 가중치로 삼아 비복원 추출([lotto_stats.py](lotto_stats.py:88) `get_number_weights`).
2. **자연수 필터**(기존 유지): 연속번호 4개 이상, 특정 10단위 구간 쏠림, 동일 끝수 쏠림 등
   "부자연스러운" 조합을 걸러내는 재시도 로직 — 이 임계값도 역대 데이터의 실제 발생률을
   직접 집계해서 정함([lotto_stats.py](lotto_stats.py:443) `THUNDER_FILTER_MAX_*`).
3. **기준값패턴 채점**(2026-08-21 신규): 운영자가 직접 조사·정리한 엑셀(패턴명/번호목록/
   최소/최대 형식)을 관리자 대시보드에 업로드하면, 이 규칙 전체(현재 380개 — 홀짝비율,
   1~23/24~45 구간, 소수/합성수/3배수 분포, 10단위 구간, "전 출현번호"(직전 회차 당첨번호+
   보너스), "이웃수"(그 번호들의 앞뒤 인접번호) 등)를 조합 후보가 몇 개나 만족하는지 채점해
   우선 채택([lotto_stats.py](lotto_stats.py:260) `get_resolved_pattern_rules`,
   `score_combo_against_pattern_rules`).
   - "이웃수" 규칙은 "자기 자신을 포함해 앞뒤 1칸"이라는 구체적 계산 규칙을 사용자가 직접
     확정함(2026-08-21 세션에서 예시 계산 대조·확인 과정 거침).
   - 소자배(소수/합성수/3배수) 허용 개수(각 1~3개), 10단위 구간별 허용 개수(1~9번대·40~45번대는
     0~2개, 나머지는 0~3개)는 사용자가 직접 지정한 수치 기준.
4. **생일/행운수(생명수)**: 가족 최대 4명의 생일을 등록하면 수비학(생명수) 계산으로 행운수
   3개를 산출해 조합에 확률적으로 포함시키는 별도 로직([lucky_numbers.py]) — 개인화된
   상징적 의미 부여 방식.

### 2.3 개발 과정에서 드러난 인간의 명시적 창작 판단(2026-08-20~21 세션 실제 기록)
- "단순 출현빈도만으로는 '데이터 근거 분석'이라 할 수 없다"는 판단 아래, 홀짝·저고·소자배·
  10단위 등 유형별 지표를 요구.
- 3종필터(자동구매 전용 검증 풀)와 번개조합의 조합 생성 로직을 절대 공유하지 말라는 명확한
  기능 분리 지시.
- "관리자가 매주 감으로 입력하던 숫자 6개"(과거 데이터 근거 없는 리스트)가 메인화면 장식용
  숫자와 실제 조합 생성 로직에 동시에 쓰이고 있던 걸 발견하고, 장식 전용으로만 남기도록
  분리 지시.
- 최종적으로는 하드코딩된 8개 지표조차 "빈약하다"고 판단해, 본인이 직접 정리한 엑셀 기준값
  패턴으로 전면 교체하도록 지시 — 이는 알고리즘의 최종 판단 기준을 사용자가 직접 큐레이션한
  사례.

[사용자 보완 필요: 소자배/10단위 등 구체적 수치 기준을 정하게 된 실전 경험/근거]

## 3. 안티/액땜조합

### 3.1 기능 설명
이미 구매한 로또 복권(QR 스캔 또는 직접입력)과 "일부러 겹치지 않는" 새 조합을 생성한다.
- **안티조합**: 입력한 줄(최대 5줄) 각각과 개별적으로 겹침이 적은 조합 생성.
- **액땜조합**: 입력한 모든 줄을 합친 전체 번호 풀과 겹침이 적은 조합 생성.

### 3.2 인간의 창작적 설계
- "반대로 해서 액땜한다"는 민속적 개념을 구체적 알고리즘(겹침 개수 상한 0~2개, 안 되면
  0~3개까지 단계적 완화)으로 번역한 것 자체가 설계적 판단 — 몇 개까지 겹쳐야 "반대조합"의
  의미가 퇴색되는지 사용자가 직접 기준을 정함(코드 주석에 "4개부터는 안티/액땜의 의미가
  퇴색된다는 게 사용자와 합의된 기준"으로 명시, [page_hedge.py](page_hedge.py:20)).
- QR 스캔 파싱 포맷(동행복권 로또 용지 QR의 `v=` 값 12자리 인코딩 규칙)을 실물 티켓 여러 장으로
  직접 대조 검증한 기록이 코드 주석에 남아있음([page_hedge.py](page_hedge.py:24)).
- 번호 추첨 방식은 번개조합과 동일한 "번호별 과거 출현 가중치 + 기준값패턴 채점" 체계를
  공유(단, 3종필터 풀은 공유하지 않음 — 명확히 분리된 저장소).

## 4. 자동구매 (3종필터 기반)

### 4.1 기능 설명
운영자가 대시보드에서 로또 6/45 전체 조합(약 814만 5,060개)을 대상으로 3단계 필터(기본필터·
절대필터·이격수필터)를 실행해 통과한 조합만 남기고, 사용자는 그 검증된 풀에서 조합을
"할당"받아 구매한다(즉석 생성이 아니라 사전 검증·배포 방식).

### 4.2 인간의 창작적 설계
- **3단계 필터 체계 자체가 고유 설계**:
  - 기본필터: 홀짝·저고·소자배(소수/합성수/3배수)·10단위 구간 등 조합 "전체"에 대한
    포함개수 최소~최대 규칙.
  - 절대필터: 특정 번호가 포함될 때만 적용되는 조건부 규칙.
  - 이격수필터: 특정 번호와 다른 번호 사이 "간격"(차이값) 조건 규칙.
  - 이 세 필터를 조합해 8,145,060개 전체 경우의 수를 순차적으로 좁혀나가는 계산 파이프라인
    설계([lotto_engine.py](lotto_engine.py) `run_admin_three_filter_staged`).
- 필터 규칙 자체를 운영자가 매주 엑셀로 직접 작성·관리(예: "소자배기본", "14-31 기본",
  "9분할" 등 세분화된 규칙 그룹명 — 로또 커뮤니티에서 통용되는 분석 기법을 직접 선별해
  엑셀화한 것으로 보임, [기본패턴.xlsx](기본패턴.xlsx) 실제 확인).
- 검증 풀에서 사용자에게 배분하는 방식도 "불규칙 간격으로 순차 할당, 회차별 풀 소진 시
  로테이션·리셋"하는 별도 설계([marketing_db.py] `allocate_lotto_combinations_random_sequential`).

[사용자 보완 필요: 기본/절대/이격수 3단계로 나눈 설계 배경, 각 필터 규칙(예: "소자배기본",
"14-31 기본" 등)을 고안하게 된 실제 분석 경험이나 참고한 이론]

## 5. 통계센터

### 5.1 기능 설명
1회~최신 회차 전체 당첨 데이터를 집계해 다양한 통계를 사용자에게 시각화해 보여준다.

### 5.2 확인된 집계 지표(고유 정의 포함)
- 핫넘버/콜드넘버(전체 회차 출현 최다/최근 N회 미출현) — [lotto_stats.py](lotto_stats.py) `calc_hot_numbers`, `calc_cold_numbers`
- 이월수(직전 회차 당첨번호가 이번 회차에도 포함된 경우) — `calc_carryover_in_last_n`
- AC값(산술적 복잡도) — 회차별 실제 값 표시 및 "이상적 구간(7~10)" 같은 해석 기준 제시
  ([user_page.py](user_page.py:1336) "AC값이 7 이상일 때 1등 당첨 확률이 통계적으로 가장 높습니다" 문구)
- 10단위 구간 분포(1번대~40번대, `DECADE_BANDS`)

### 5.3 인간의 창작적 설계
- 단순 숫자 나열이 아니라 "이상적 구간", "위험 신호" 같은 해석적 코멘트를 붙여 일반
  사용자가 이해할 수 있는 형태로 가공한 것 자체가 편집적 창작 요소.
- 어떤 지표를 보여줄지(핫/콜드/이월수/AC값/구간분포)의 선택 자체가 로또 분석 커뮤니티의
  여러 기법 중 사용자가 선별한 결과.

## 6. 타로점 (감정위로)

### 6.1 기능 설명
전통적인 "점술"이 아니라 **정서적 위로**를 목적으로 재해석한 타로 기능. 사용자가 10개
감정 카테고리(예: 번아웃/무기력, 인간관계 상처, 미래에 대한 불안 등) 중 하나 → 3개 소분류
중 하나를 선택하면, 78장(메이저 22 + 마이너 56) 중 무작위 1장이 "손편지" 형식으로
제시된다. 하루 1장 제한.

### 6.2 인간의 창작적 설계 — 가장 뚜렷한 독자적 창작 요소

**(1) 카드 이미지와 해석 텍스트의 완전한 분리**
카드 이미지는 라이더-웨이트-스미스(Rider-Waite-Smith) 덱으로, 미국 내 퍼블릭 도메인임을
데이터 파일에 명시([tarot_data.py](tarot/tarot_data.py:10) "출처: Rider-Waite-Smith 덱, 미국 내
퍼블릭 도메인"). 즉 **저작권 주장의 대상은 이미지가 아니라, 그 위에 새로 얹은 전면적으로
독창적인 해석 텍스트**다 — 전통적 타로의 "점괘/예언" 해석을 전혀 쓰지 않고, 완전히 새로운
심리 상담적 텍스트 체계로 대체함.

**(2) 78장 × 6개 필드의 고정 구조 설계 (독자적 프레임워크)**
카드마다 `intro`(카드 소개) → `state`(현재 심리상태 반영) → `comfort`(위로) →
`acceptance`("~해도 괜찮아요" 형식의 허용 선언) → `moment`(호흡·신체감각에 집중하는
마인드풀니스 유도 문장) → `hope`(희망적 전망), 이렇게 6단계로 구성된 고정 틀을 78장 전부에
일관 적용([tarot_data.py](tarot/tarot_data.py:90) 예시).
- 이 중 **`moment`(마인드풀니스 유도)는 전통적 타로 해석에 없는 요소**로, "손을 가슴에
  올려보세요", "발바닥이 바닥에 닿는 느낌을 느껴보세요" 같은 신체 감각 기반 접지(grounding)
  기법을 카드 상징과 결합해 매 장마다 새로 쓴 것으로 확인됨 — 심리상담 기법(마인드풀니스)과
  타로 카드 상징을 결합한 독자적 창작 프레임.

**(3) 명시적으로 문서화된 집필 원칙(가장 강력한 창작성 근거)**
콘텐츠 원본 문서([타로_콘텐츠_시적확장판_74장.md](tarot/타로_콘텐츠_시적확장판_74장.md:3~4))에
집필 규칙이 명문화되어 있음:

단정적으로 지목하지 않고 "~때가 있어요"라는 완곡하고 보편화된 화법을 의도적으로 유지하며,
명령형("~하세요")을 피하고 권유형을 쓰는 등 구체적인 문체적 창작 판단이 명문화되어 있다.

**(4) 감정 카테고리 설계(10 × 3 = 30개 진입점)**
막연히 "고민을 입력하세요"가 아니라, 번아웃/무기력·인간관계 상처·미래에 대한 불안·자존감
흔들림·외로움·반복되는 일상에 지침·후회/미련·화/억울함·사랑/연애 고민·작은 희망이
필요할 때, 이렇게 10개 카테고리를 선정하고 각각 3개 세부 상황("일에 완전히 지침",
"아무것도 하기 싫음", "쉬어도 쉰 것 같지 않음" 등)까지 세분화해, 그 조합마다 별도의 공감
문장을 미리 작성함([tarot_data.py](tarot/tarot_data.py:30) `SUBCATEGORIES`, 총 30개 문장). 이
분류 체계 자체가 독자적 기획.

**(5) 시각적 연출 설계**
카테고리마다 고유 파스텔 색상과 이모지 아이콘을 배정([tarot_page.py](tarot/tarot_page.py:44,57)),
손글씨 폰트(Gaegu 등)를 활용한 "손편지" 형식 결과 화면, 하루 1장으로 제한해 "매일의 의식"처럼
느껴지게 한 페이싱 설계([tarot_page.py](tarot/tarot_page.py:38) `MAX_DAILY_DRAWS = 1`).

## 7. 전체 개발 과정에서 나타난 "인간의 창작적 표현" 패턴 (종합)

이 앱의 모든 기능에서 공통으로 관찰되는 인간 저작성의 근거:

1. **알고리즘의 판단 기준 자체를 사용자가 결정**: AI가 통계 기법을 제안해도, 실제 채택
   여부·구체적 수치(소자배 1~3개, 이격수 겹침 상한 등)는 전부 사용자가 최종 결정.
2. **기존 AI 제안을 거부하고 방향을 재설정한 사례가 다수 존재**(세션 로그에 실제 기록):
   예) AI가 "3종필터 풀을 번개조합에도 재사용하자"고 제안했으나 사용자가 명확히 거부하고
   완전히 독립된 설계를 지시함. AI가 만든 8개 하드코딩 지표를 "빈약하다"고 판단해 직접
   조사한 엑셀 기준으로 전면 교체 지시.
3. **콘텐츠(텍스트)의 문체·구조 원칙을 명문화**: 타로 콘텐츠의 집필 규칙(문장 수, 화법,
   금지어 등)이 문서로 남아있어, 결과물이 임의의 AI 산출물이 아니라 정해진 창작 규칙을
   따른 것임을 보여줌.
4. **실제 데이터/실물 자료와의 대조 검증**: QR 코드 포맷을 실물 로또 용지로 대조 검증,
   패턴 규칙을 1237회 전체 실제 당첨 데이터로 집계 검증 — 창작물이 근거 없는 추측이 아니라
   검증된 사실 위에 구축됐음을 보여주는 절차적 증거.
