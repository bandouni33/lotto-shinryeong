1. 준비한 것 3가지
---------------------------------------------------------------------
① 서버 로그 캡처 — run_server.ps1
   서버 stdout(렌더마다 한 줄: `[dbtrace] page=main calls=N db_ms=.. script_ms=..`)을
   `server_out.log` 로 남긴다. `-u`(언버퍼) 필수 — 파일로 리다이렉트하면 블록 버퍼링돼
   줄이 뭉텅이로 늦게 온다. `*.log` 는 .gitignore 대상이라 커밋되지 않는다.
   ※ 이 파일이 **실제 사용자 렌더**의 script_ms·DB 왕복 수·db_ms 를 유일하게 남기는 지점이다.

② 관측자 — scratch/observe_live_traffic.py (읽기 전용, 앱·DB에 아무것도 쓰지 않는다)
   60초마다: HTTP 상태/지연 + **웹소켓 세션 1개로 실제 렌더 1회**(script_ms, 대기화면 여부)
   + 서버 프로세스 RSS/CPU + server_out.log 의 새 [dbtrace] 줄에서 **실사용 렌더** 통계.
   → CSV 한 줄씩 + 끝에 요약 JSON. 프로브 자신의 렌더는 `real_user_renders_est` 에서 빼도록
     시작 시점의 로그 위치를 기억한다(안 하면 과거 렌더가 실사용으로 둔갑한다 — 실제로 그렇게
     잘못 세다가 고쳤다).

③ 예약 작업 — register_observer_task.ps1
   토요일 19:30에 4시간 동안 ②를 자동 실행(추첨 20:45 + 직후 버스트를 덮는다).
   결과: scratch\live_observation_2026-10-10.csv / .json
   제거: Unregister-ScheduledTask -TaskName "LottoShinryeongObserve" -Confirm:$false

4. 이번 준비 중 발생한 사고 (정직하게 기록)
---------------------------------------------------------------------
· 제가 run_server.ps1 에 PowerShell `*>> $logFile` 리다이렉트를 넣었더니, 콘솔 없는
  기동(작업 스케줄러/watchdog → Start-Process -WindowStyle Hidden)에서 **서버가 뜨지 않았다**.
  증상: server_out.log 파일만 생성되고 비어 있음 + 8501 미점유.
  · 실제 영향: **약 110초 다운타임** (22:18:48 watchdog 시도 → 22:20:31 복구).
    비공개 테스터 시간대(밤 10시 18분)였고, 관측 도구의 http_failures 는 0이지만
    **다운타임 동안의 접속 시도 여부는 알 수 없다**(그때는 관측 자체가 꺼져 있었다).
  · 수정: cmd 의 `>>` 리다이렉트로 우회(`cmd /c "python -u -m streamlit run app.py ... >> log 2>&1"`)
    → 재기동 확인(PID 13812, health=ok, 로그에 Uvicorn 기동 줄 기록됨).
  · 재발 방지: **런처(run_server.ps1)를 고치면 그 자리에서 실제 기동까지 확인한다.**
    다음부터 이 파일을 수정할 때는 watchdog 을 부르고 30초 뒤 health 를 반드시 본다.
